# Generative mode (TRELLIS.2)

Generative mode adds a second way to produce a model. Instead of building
geometry procedurally from a `SceneSpec`, it takes a base mesh generated by
Microsoft [TRELLIS.2](https://github.com/microsoft/TRELLIS.2) (image/text → 3D
with PBR) and runs it through the King3D quality pipeline to make it game-ready.

The procedural mode is unchanged and remains the default. Generative mode lives
beside it, with its own spec, its own orchestrator, and its own gates.

## Why it is a separate mode

`SceneSpec` describes an object as a closed set of primitive strategies, and its
gates reason about named components, identity parts and per-component
proportions. A TRELLIS mesh is a single opaque surface — none of that vocabulary
applies. Rather than bend `SceneSpec` to hold something it was not designed for,
generative mode has a small parallel schema (`GenerativeSpec`,
`src/spec/generative-spec.ts`) that records only where the mesh came from and the
deterministic recipe used to clean it.

## Honest caveats

- **Philosophy.** This mode uses a diffusion/generative model that needs a GPU
  (≥24 GB VRAM, Linux, CUDA 12.4) — the opposite of the procedural pipeline's
  "no black box, no API key" design. It is opt-in for exactly that reason.
- **Licence (reviewed 2026-10-11).** TRELLIS.2 code and the `TRELLIS.2-4B` weights
  are **MIT**, but the stock textured-GLB export (`o_voxel.postprocess.to_glb`)
  **imports and uses `nvdiffrast`** (NVIDIA, **non-commercial**) to bake the
  texture — confirmed by a static source check, not just the README. So a
  **commercial** build is **not** clean out of the box: you must replace the
  rasterizer, export geometry-only (no baked PBR), or licence nvdiffrast.
  Research/non-commercial use of the stock pipeline is fine. Full findings and
  options: [`services/trellis/README.md`](../services/trellis/README.md).
- **Repair is best-effort.** `repair.clean` welds, drops loose geometry, dissolves
  degenerate faces, fills holes and makes normals consistent. It is not true
  retopology and cannot guarantee a manifold result for every input; the
  `generative_integrity` gate reports what remains.
- **Geometry-only, King3D owns the material.** To stay off nvdiffrast (commercial
  path), the service exports only geometry — no baked PBR texture. King3D then
  assigns the spec's default material (`spec.material`) and unwraps a fresh UV, so
  the output is a clean, King3D-owned PBR asset. A textured GLB fed in directly is
  still handled: meshes that already carry a UV/material are left as-is.

## Architecture

```
image/prompt ─▶ TRELLIS.2 service (geometry-only, Python/CUDA, HTTP) ─▶ base.glb
                                                           │
   ┌───────────────────────────────────────────────────────┘
   ▼
import.glb → repair.clean → material.assign (missing only) → uv.unwrap (missing
           only) → optimize.decimate → export.glb → import.glb (verify)
           → generative gates → report.json
```

- **Inference service** — `services/trellis/` (FastAPI). The GPU concern stays
  entirely behind an HTTP boundary, so the same service runs locally or in the
  cloud; King3D only changes `KING3D_TRELLIS_URL`.
- **Client** — `src/integrations/trellis/client.ts` (`HttpTrellisProvider`,
  `MockTrellisProvider`).
- **Repair op** — `blender/ai3dlib/repair.py` (`repair.clean`).
- **Orchestrator** — `src/pipeline/generative-run.ts` (`buildFromGenerated`).
- **Gates** — `src/pipeline/generative-gates.ts` (`evaluateGeneratedGates`),
  including the `generative_integrity` gate.

## Other generators
Generative mode is not tied to TRELLIS.2. Every generator is an HTTP service with the
same contract (`GET /healthz`, `POST /generate` -> GLB), registered in
`src/integrations/meshgen/`. Pick one with `--generator` (CLI), the `generator`
argument (MCP) or the dashboard's Generator list.

| Generator | Licence | Default |
|---|---|---|
| `trellis2` | MIT (see above) | on |
| `hunyuan3d` | Tencent community licence: **excludes the EU, UK and South Korea, including use of the output** | off; set `KING3D_GEN_HUNYUAN3D_URL` |

Hunyuan3D is a slot only: nothing from Tencent is bundled, and an unconfigured
generator is refused before any run is created. Read
[`services/hunyuan3d/README.md`](../services/hunyuan3d/README.md) before enabling it.

## Configuration

| Env var | Default | Meaning |
|---|---|---|
| `KING3D_TRELLIS_MODE` | `http` | `http` (call the service) or `mock` (fixture GLB, no GPU) |
| `KING3D_TRELLIS_URL` | `http://127.0.0.1:8900` | Base URL of the service (local or cloud) |
| `KING3D_TRELLIS_TIMEOUT_MS` | `300000` | Budget for one generation request |
| `KING3D_TRELLIS_MOCK_GLB` | `tests/fixtures/trellis/base.glb` | Fixture returned in mock mode |
| `KING3D_GEN_HUNYUAN3D_URL` | unset | Base URL of your own Hunyuan3D service; unset keeps the generator off |

## Running it

Mock (no GPU — for development and CI):

```bash
KING3D_TRELLIS_MODE=mock node src/cli/index.ts gen-trellis \
  --image tests/fixtures/mug_reference.png --run-id gen_demo
node src/cli/index.ts viewer gen_demo
```

Against a real service (local or cloud), once the licence is cleared and the
model is wired in per `services/trellis/README.md`:

```bash
KING3D_TRELLIS_MODE=http KING3D_TRELLIS_URL=http://<host>:8900 \
  node src/cli/index.ts gen-trellis --image path/to/photo.png
```

Also available as the MCP tool `king3d_generate` and the dashboard route
`apiCreateGenerativeRun` — all three call the same `buildFromGenerated`.

## Output

A generative run writes to `runs/<id>/` like any other run:

- `generative-spec.json` — the spec (source, generator, repair recipe, quality)
- `source/base.glb` — the raw mesh from TRELLIS (or the mock)
- `scene.blend`, `export/model.glb`
- `report.json` — gate results and scores
